# 待机功耗控制（Idle Power Control）

ColorOS 15 / 16 / 17 通用的 LSPosed 熄屏省电模块，**不是一加 13 专用**。一加、OPPO、realme 的 ColorOS / RealmeUI 机型都可以直接用，Android 13+ 的其他机型多数也能运行（用到 OPPO 系服务的部分功能会按机型自动降级）。

已在以下机型实测：

- 一加 13（PJZ110，ColorOS 16 / Android 16）
- OPPO Find X8 Ultra（PKJ110，Android 17）
- OPPO Find N3 典藏版
- OPPO Find X9（PLG110，ColorOS 17 / Android 17，天玑平台）—— 目前只有诊断模式基线（熄屏 112 分钟掉 1%，约 0.5%/h），省电档还没复测
- 一加 15（PYF110，ColorOS 17 / Android 17）—— 目前只有亮屏段样本，熄屏数据还在等

## 它做什么

- **熄屏接管唤醒锁**：按预设清单拦掉闹钟、广播、部分唤醒锁，限制第三方应用靠定时唤醒把系统叫醒
- **闹钟限流**：`ALARM_RATE=N` 让每个包每分钟最多调度 N 个闹钟，超了直接丢。微信 `/ QQ` 那种熄屏后一分钟排几十次闹钟的，这是整夜掉电的主因；极致省电档默认 4 次/分，代价是消息可能延迟
- **强制深睡**：熄屏一段时间后直接 force-idle，让系统进入 Doze 深睡，而不是原地待机
- **三档预设**：正常（3 条规则）/ 省电（13 条）/ 极致省电（19 条），可自己改 `BLOCK=` 清单
- **流量省电**：关闭 / 温和 / 彻底三档。温和档开系统数据省电并把微信、企业微信、QQ、短信加入白名单；彻底档熄屏即断移动数据，每 15 分钟开 20 秒窗口收消息。连 Wi-Fi 时不干预，亮屏立刻恢复
- **插电不接管**：插着电熄屏时不做深睡、不强停应用、不断移动数据（系统本来就不让插电进 Doze），拔电后条件满足会自动接上
- **使用统计**：亮屏 / 熄屏时长与掉电分开计，时长按进行中的那一段实时累计；充满电自动清零（可关，`FULL_RESET=1`），也能手动「重置统计」，卡片底部显示统计起点
- **功耗曲线**：15 秒采样一次电池节点，画成功率（mW）与温度曲线，只保留最近 24 小时，双指缩放、双指拖动
- **唤醒榜**：本次息屏期间各应用唤醒次数排行，一眼看出谁在偷偷耗电
- **数据只在本地**：全部写在 `/data/system/idlepower.*`，不上传、不联网

## 安装

1. 手机需要 root（Magisk / KernelSU / APatch）和 LSPosed
2. 安装本模块 APK，在 LSPosed 里启用，**作用域只勾「系统框架」**，然后重启手机
3. 打开 App，首次会请求 root，点允许并勾选「记住选择」
4. 进「功能」页选预设，「设置」页可单独调采样频率、息屏延迟、流量省电档位

升级模块后必须重启一次，新版本才会真正注入（不重启会继续跑内存里的旧模块）。

## 版本

当前 v8.8（versionCode 193）

- 修掉熄屏时长少算：整机深睡时 `SystemClock.uptimeMillis` 不走（不含 suspend 时间），用它累计会把整夜熄屏漏掉，界面只显示十几分钟。改用 `SystemClock.elapsedRealtime` 累计，亮熄屏两段之和才对得上「统计起点 → 现在」
- 修掉唤醒榜「本次息屏」时间窗错乱：会话结束后只记了结束时刻，起点没重开，后面每次息屏都沿用上一段的时间，窗口永远停在 1 分钟以内，计数却一直涨（出现过「1 分钟 1546 次」）。现在会话结束即标记 complete，下次息屏重新计时并清空计数；亮屏时标题显示「上次息屏」，看到的就是那一段的真实窗口
- 亮屏时榜单不再清空，打开 App 能直接看到刚过去的一夜，不用等下一段息屏
- 新增 `ALARM_RATE`：每个包每分钟最多允许调度 N 个闹钟，超过就丢掉这次调度，只在熄屏且过了 `DELAY` 秒后生效，亮屏立刻恢复。日志会记一条 `ARATE ... 超过 N 次/分，开始丢弃`
- 起因：Find X8 Ultra 那台跑省电档，强制 IDLE 连着九个小时，还是 2.8%/h。45 分钟窗口里微信 `MicroMsg.Alarm` 排了 1628 次（36 次/分）、QQ `MSF:WakeLock:Alarm` 1369 次、`android *alarm*` 1560 次；之前只拦 `BLOCK` 名单里的包，微信在 `PROTECT` 里，闹钟一次都没限过
- 用法：极致省电档默认 `ALARM_RATE=4`；省电档默认 `0`，想压就写 `ALARM_RATE=6`；写回 0 即完全恢复即时推送，不用重装
- 代价说明：闹钟被丢，微信 / QQ 的拉取会被推迟，可能十几分钟才收到消息。这就是这个开关本身要换的东西
- 修掉息屏会话汇总算错：功率点在曲线文件里带符号（放电为负），旧逻辑只统计大于 0 的点，整夜放电全被跳过，日志里成了「平均 -1mW 峰值 -1mW 点数 0」。现在按绝对值算，没点就写「无采样」
- 修掉「彻底」档白名单其实没加进去：取 uid 用的是 `dumpsys package`，输出被截断读不到 `userId=`，日志里一直是「白名单 0/4」。结果熄屏断数据后微信整夜重试（一晚 700 多次唤醒）。改用 `cmd package list packages -U` 取 uid，加不进去的包也会写进日志
- 诊断报告里的「管理器版本」之前固定写 8.0，改成真实版本号
- 重置统计原地生效：点一下界面立刻归零，统计页每 5 秒自动刷新，模块确认后直接显示新起点，不用退出去再进来
- 修掉重置后「亮屏时长 / 熄屏时长 / 熄屏掉电」显示成「—」的问题：时长把正在进行的那一段实时算进去，掉电也实时累计；清零后显示 0 分钟 / 0.0%
- 新增「充满自动清零」开关（默认开，`FULL_RESET=1`）：插电且 `status=FULL` 时自动清零，和系统「上次充满电后」同口径；不想要可以一键关掉
- 插着电熄屏时不再接管。系统不让插电进 Doze，强推只会被踢出来再推回去；现在深睡、熄屏清理（含视频应用强停）、流量省电全部让开，只保留功率曲线和唤醒榜，拔电后照旧自动接上
- 修掉「彻底」档不生效：system_server 是 uid 1000，`cmd netpolicy` / `cmd phone` 的 shell 接口只放行 shell 与 root，之前一直被 SecurityException 挡回，现在改走 su 并用 `settings get global mobile_data` 回读确认
- 修掉 `Context` 为空导致的断数据失败，补了系统 Context 的三级获取
- 飞行模式下自动跳过断数据，不再做无意义的切换
- 版本号误判、唤醒榜标题竖排、状态行标签竖排一并修好
- 主题：经典 / 清爽蓝 / MIUIX 三套风格各有日夜，切换带圆形展开且不跳页

> 注意：`185-8.6` 那一版的重置统计有显示问题（要退出页面才刷新）、白名单也是坏的，已被本版取代，请装 `193-8.8`。

## 反馈：欢迎把诊断报告发给我

模块的省电效果高度依赖机型和 ROM，**很需要真实机器的数据来继续优化**。

导出方法：App「关于」页 →「一键诊断 / 导出报告」，会生成一个 `待机功耗控制-报告-MMDD-HHMM.txt`，里面是配置、模块心跳、运行日志和系统诊断（`dumpsys` 片段）。

发给我：酷安私信或评论区 **@污黄瓜地**，或者在 GitHub Issues 里贴上来。

发之前顺手说明几点，定位会快很多：

- 机型 + ROM 版本 + Android 版本
- 当时用的预设（正常 / 省电 / 极致省电）和流量省电档位
- 熄屏时是否连着 Wi-Fi、后台留了哪些应用、有没有放歌或导航
- 大致现象：掉电百分比、熄屏时长、想解决的具体问题

报告里没有账号、手机号、位置这类个人信息，只有功耗相关的系统输出，可以放心发。有了不同机型、不同 ROM 的报告，才能把规则清单和深睡策略继续调准。
